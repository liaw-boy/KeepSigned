# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

KeepSigned is a macOS menu-bar app (SwiftUI, macOS 15+) that keeps iOS apps signed with a free Apple ID alive: free-account profiles expire after 7 days, so it rebuilds the user's Xcode project with `xcodebuild -allowProvisioningUpdates` and installs it wirelessly with `xcrun devicectl`. It is meant for non-programmers (setup wizard, Traditional Chinese UI). It only re-signs apps built from source; it does not re-sign arbitrary .ipa files and never stores an Apple ID — it relies on the account already signed in to Xcode.

## Commands

The `.xcodeproj` is generated by XcodeGen from `project.yml` and is gitignored — regenerate after adding/removing files or changing build settings:

```sh
xcodegen generate
xcodebuild build -project KeepSigned.xcodeproj -scheme KeepSigned -derivedDataPath build
xcodebuild test  -project KeepSigned.xcodeproj -scheme KeepSigned -destination 'platform=macOS' -derivedDataPath build
# single class / single test
xcodebuild test ... -only-testing:KeepSignedTests/ValidatorTests
xcodebuild test ... -only-testing:KeepSignedTests/ValidatorTests/testNeedsRenewal
```

Set `KEEPSIGNED_HOME=/abs/path` to run the app (or a "fresh user" check) against a throwaway config dir instead of `~/Library/Application Support/KeepSigned/`.

Release: bump `VERSION` (+ `CHANGELOG.md`), then `scripts/release.sh` → `dist/KeepSigned-<v>.zip` + signed `dist/appcast.xml` to upload to GitHub release `v<v>` (the script never tags/uploads). It signs with the Sparkle EdDSA key in the login keychain; Sparkle CLI tools live in `build/SourcePackages/artifacts/sparkle/Sparkle/bin/`. `KEEPSIGNED_LOCAL_TEST=1` plus `SPARKLE_FEED_URL`/`SPARKLE_PUBLIC_KEY`/`DOWNLOAD_URL_PREFIX`/`SPARKLE_KEY_FILE` builds a local-feed test pair into `dist/test/` (useful for an end-to-end old→new update test with a throwaway bundle ID); without the flag those vars are refused.

App icon: edit `design/AppIcon.svg`, then `scripts/make-icon.sh` regenerates `KeepSigned/Assets.xcassets/AppIcon.appiconset`.

`SampleApp/` is a separate iOS test app with its own `project.yml`; unlike the main project, its `SampleApp.xcodeproj` **is** committed so users without XcodeGen can pick it in the app.

## Architecture

- `ResignService` (`@MainActor @Observable`) is the single source of state, shared by `MenuView`, `OnboardingView` and `SettingsView`. It runs `renewDue()` hourly, on Mac wake and at launch; only one target re-signs at a time (`runningID`).
- Re-sign pipeline (`ResignService.build`): `ProfileCache.moveAside` → `xcodebuild` → read expiry from the built app's `embedded.mobileprovision` (`ProvisioningProfile`, via `security cms -D`) → `devicectl device install app`.
  - Moving the app's cached profile aside is essential: otherwise Xcode reuses the unexpired profile and the expiry does not move. Profiles are moved (never deleted) to `ProfileBackup/<bundleID>/` and restored if the build fails. Matching is exact on `application-identifier`; wildcard profiles never match.
  - Auto-renew only fires when a known expiry is within `thresholdHours`. Unknown expiry never auto-renews — the first sign must be started by hand.
- Per-user values (Team ID, bundle prefix) live in `settings.json` and are passed to xcodebuild as `DEVELOPMENT_TEAM=` / `BUNDLE_ID_PREFIX=` overrides, so user projects (which use `$(BUNDLE_ID_PREFIX).app`) need no per-user edits and the repo contains no personal data.
- `CommandRunner` runs tools directly via `Process` (no shell) and writes output to a temp file rather than a pipe so verbose xcodebuild can't stall. Full output goes to `resign.log`; users see short Chinese messages from `buildFailureReason`.
- `Validator` gates every value that becomes a CLI argument (scheme, device UDID, project path, Team ID, prefix, bundle ID) and rejects leading `-` (option injection) and non-normalized paths. Keep new CLI arguments behind the same kind of check, and add a test.
- `EnvironmentCheck` (wizard detection: Xcode, Apple ID, Team ID, device/Developer Mode) and `Devices` (device list/sorting) parse `defaults export com.apple.dt.Xcode` and `devicectl --json-output`; parsing is split into pure functions so tests feed fixture data.
- Auto-update: Sparkle 2 (`Updater.swift`). Feed URL and public key are build settings in `project.yml` substituted into `KeepSigned/Info.plist` (merged with the generated plist). Feed must be signed (`SURequireSignedFeed`); CFBundleVersion is derived from VERSION as `major*10000+minor*100+patch` so it always increases.
- Testability pattern: side effects are injected (e.g. `ProfileCache.decode`, `profileCache:` init param) or isolated into `nonisolated static` pure functions (`buildArguments`, `buildFailureReason`, `parse*`) that tests call directly.

## Constraints

- App Sandbox and Hardened Runtime are off on purpose (it must run xcodebuild/devicectl); ad-hoc signed (`CODE_SIGN_IDENTITY: "-"`).
- Never put real Team IDs, bundle prefixes, device UDIDs, names or Apple IDs in code, tests or docs — use invented values (`dev.example`, fake UDIDs).
- Config files are written 0600, config dir 0700.
